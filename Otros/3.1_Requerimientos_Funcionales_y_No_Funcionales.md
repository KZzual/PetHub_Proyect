# 3.1 Requerimientos Funcionales y No Funcionales (PetHub)

Este documento actualiza y alinea los requerimientos con la implementación real del proyecto PetHub (Flutter/Dart + Firebase: Auth, Firestore, Storage, Messaging, Hosting; Google Vision; notificaciones locales; chat; análisis de imágenes; vistas recientes).

## Requerimientos Funcionales

- Autenticación
  - RF-001: El sistema debe permitir registrarse con email y contraseña.
  - RF-002: El sistema debe iniciar sesión con email y contraseña.
  - RF-003: El sistema debe verificar el correo electrónico antes de habilitar funciones sensibles.
  - RF-004: El sistema debe permitir restablecer contraseña por correo.
  - RF-005: El sistema debe cerrar sesión explícitamente.

- Perfil de usuario
  - RF-006: El sistema debe crear el perfil de usuario al momento del registro.
  - RF-007: El usuario debe poder editar nombre, comuna, teléfono y descripción.
  - RF-008: El usuario debe poder subir una foto de perfil.
  - RF-009: El sistema debe almacenar y actualizar `fcm_token` para notificaciones push.
  - RF-010: El sistema debe mostrar los datos públicos del perfil en pantallas relacionadas.

- Publicación y gestión de mascotas
  - RF-011: El usuario debe poder crear una publicación de mascota con foto.
  - RF-012: La publicación debe incluir especie, raza, género, edad, ubicación, descripción.
  - RF-013: El sistema debe permitir editar publicaciones propias.
  - RF-014: El sistema debe permitir cambiar el estado de la mascota (En Adopción/Adoptado).
  - RF-015: El sistema debe listar mascotas por orden de creación.
  - RF-016: El sistema debe permitir filtrar mascotas por especie, género y estado.
  - RF-017: El sistema debe mostrar detalle de mascota con foto y datos completos.

- Búsqueda y exploración
  - RF-018: El sistema debe permitir buscar por nombre y/o filtros combinados.
  - RF-019: El sistema debe guardar vistas recientes por usuario.
  - RF-020: El sistema debe identificar cambios de estado respecto a la última vista.

- Chat y mensajería
  - RF-021: El usuario debe poder iniciar chat con el publicador de una mascota.
  - RF-022: El sistema debe reutilizar un chat existente entre dos usuarios si ya existe.
  - RF-023: El sistema debe enviar y recibir mensajes en tiempo real.
  - RF-024: El sistema debe marcar mensajes como vistos.
  - RF-025: El sistema debe actualizar `last_message` y `last_timestamp` del chat.
  - RF-026: El sistema debe mostrar la lista de chats del usuario.

- Notificaciones
  - RF-027: El sistema debe recibir notificaciones FCM cuando aplique.
  - RF-028: El sistema debe mostrar notificaciones locales para eventos relevantes.
  - RF-029: El sistema debe permitir configurar el canal de notificaciones en Android.

- Análisis de imágenes (AI)
  - RF-030: El sistema debe validar EXIF para asegurar que la imagen es reciente/propia cuando aplique.
  - RF-031: El sistema debe invocar Google Vision para etiquetar y describir la imagen.
  - RF-032: El sistema debe generar una descripción automática de la mascota basada en etiquetas.
  - RF-033: El sistema debe cachear resultados de visión por hash (SHA-1) para evitar costos repetidos.

- Almacenamiento y medios
  - RF-034: El sistema debe subir imágenes de perfil y de mascotas a Firebase Storage.
  - RF-035: El sistema debe obtener la URL pública de la imagen para mostrarla en la app.

- Accesibilidad y experiencia
  - RF-036: El sistema debe mostrar mensajes de error legibles ante fallos de red/auth.
  - RF-037: El sistema debe proporcionar feedback visual en operaciones largas (carga/spinners).

- Web y hosting
  - RF-038: El sistema debe publicar páginas estáticas de privacidad y términos en `public/`.
  - RF-039: La versión web debe inicializar Firebase y operar con funcionalidades compatibles (navegación, lectura, listado).

- Administración (mínima)
  - RF-040: El sistema debe permitir a usuarios cambiar su `role` si se amplía (adoptante/rescatista) bajo reglas definidas.
  - RF-041: El sistema debe permitir al dueño del recurso (publicación) eliminar su propia publicación.

- Seguridad y cumplimiento
  - RF-042: El sistema debe rechazar operaciones si el usuario no está autenticado.
  - RF-043: El sistema debe impedir editar recursos que no son del usuario propietario.

- Observabilidad y métricas (básico)
  - RF-044: El sistema debe computar conteos de notificaciones de cambios de estado desde `recent_views`.
  - RF-045: El sistema debe permitir estadísticas simples (número de publicaciones por estado/especie).

- Integraciones
  - RF-046: El sistema debe usar `firebase_options.dart` para inicialización multiplataforma.
  - RF-047: El sistema debe usar `shared_preferences` para pequeñas preferencias locales.

- Rendimiento percibido
  - RF-048: El sistema debe paginar o limitar resultados en listados para evitar bloqueos.
  - RF-049: El sistema debe cachear datos frecuentes (p.ej., última lista vista) cuando aplica.

- Internacionalización (mínima)
  - RF-050: El sistema debe soportar textos en español coherentes y legibles.

- Compatibilidad multiplataforma
  - RF-051: La app debe ser ejecutable en Android, iOS, Web y Desktop (según soporte Flutter), con degradación controlada donde falten capacidades.

- Gestión de errores
  - RF-052: El sistema debe registrar y reportar fallos críticos en inicialización Firebase.

- Instalación y configuración
  - RF-053: El sistema debe leer `google-services.json` en Android y equivalentes en iOS/web.

- Privacidad
  - RF-054: El sistema debe exponer políticas de privacidad y términos accesibles desde la app.

- Mantenimiento de sesiones
  - RF-055: El sistema debe recordar la sesión del usuario entre aperturas de la app.

- Soporte de imágenes
  - RF-056: El sistema debe permitir seleccionar imágenes desde galería/cámara.

- Consistencia de datos
  - RF-057: El sistema debe validar campos obligatorios antes de publicar una mascota.

- Estados y transiciones
  - RF-058: El sistema debe manejar correctamente el cambio de estado de mascota y reflejarlo en listas y detalle.

- Navegación
  - RF-059: El sistema debe permitir navegación consistente entre pantallas principales: inicio, crear publicación, perfil, chats, detalle.

- Seguridad de contenido
  - RF-060: El sistema debe prevenir publicación de contenido no relacionado (mediante validaciones básicas y/o AI).

## Requerimientos No Funcionales

- Calidad de código
  - RNF-001: El código debe seguir convenciones de Flutter/Dart (nombres, organización).
  - RNF-002: Debe existir separación de responsabilidades: `services/`, `screens/`, `widgets/`, `utils/`.

- Rendimiento
  - RNF-003: El tiempo de arranque debe ser razonable (<3s en Android gama media, objetivo).
  - RNF-004: Listados deben renderizarse con scroll fluido sin bloqueos perceptibles.

- Disponibilidad y confiabilidad
  - RNF-005: La app debe funcionar offline de forma limitada (lectura de últimos datos cacheados cuando sea posible).
  - RNF-006: La app debe degradar funcionalidad cuando los servicios de Firebase no estén disponibles, mostrando mensajes claros.

- Seguridad
  - RNF-007: Las reglas de seguridad de Firestore deben restringir lectura/escritura por usuario autenticado y propietario.
  - RNF-008: Las imágenes deben estar protegidas mediante reglas de Storage adecuadas.
  - RNF-009: Los tokens FCM no deben exponerse en logs ni pantallas.

- Privacidad y cumplimiento
  - RNF-010: Debe cumplirse con la política de privacidad y consentimiento de notificaciones.
  - RNF-011: No se debe almacenar información sensible innecesaria.

- Mantenibilidad
  - RNF-012: Los servicios deben ser reutilizables y con APIs estables.
  - RNF-013: El código debe minimizar dependencias estrechas entre UI y datos.

- Portabilidad
  - RNF-014: La app debe compilar en Android/iOS/Web/Windows/macOS/Linux (según soporte de dependencias) con cambios mínimos.

- Observabilidad
  - RNF-015: Debe existir logging básico en operaciones críticas (auth, subida de imagen, chat).
  - RNF-016: Debe contemplarse manejo de excepciones controlado en inicialización de Firebase.

- Experiencia de usuario
  - RNF-017: La app debe mantener consistencia visual y navegación clara.
  - RNF-018: Los mensajes de error deben ser comprensibles y en español.

- Integración con terceros
  - RNF-019: Las credenciales de Google Vision deben gestionarse de forma segura.
  - RNF-020: Las respuestas de Vision deben cachearse para mejorar latencia y costos.

- Escalabilidad
  - RNF-021: La estructura de Firestore debe soportar crecimiento moderado en chats y publicaciones.
  - RNF-022: El sistema debe permitir particionar vistas o paginar para mantener rendimiento.

- Pruebas
  - RNF-023: Debe existir al menos un test de widget básico y la app debe compilar sin errores.

- Documentación
  - RNF-024: Debe existir README con pasos de configuración y despliegue básico.
  - RNF-025: Debe existir documentación de endpoints/colecciones (como el DBML adjunto).

- Localización
  - RNF-026: Textos y formatos deben ser adecuados para español (tildes, fechas).

- Compatibilidad de versiones
  - RNF-027: Las dependencias Firebase deben alinearse con el SDK de Flutter usado.

- Seguridad de datos
  - RNF-028: Validar tipos y rangos en formularios antes de enviar a Firestore.

- Tolerancia a fallos
  - RNF-029: En fallos de red, reintentar operaciones idempotentes (subida de tokens, lecturas).

- Despliegue
  - RNF-030: La app web debe poder desplegarse en Firebase Hosting con configuración adecuada.

- Caché y almacenamiento local
  - RNF-031: Preferencias y estados simples deben persistir vía `shared_preferences`.

- Accesibilidad
  - RNF-032: Contraste adecuado y tamaños de fuente legibles en pantallas clave.

- Seguridad en contenido
  - RNF-033: Evitar carga de imágenes con metadatos sospechosos cuando aplique.

- Notificaciones
  - RNF-034: Configurar canales de notificación con importancia adecuada en Android.

- Red y consumo
  - RNF-035: Optimizar tamaño de imágenes subidas (compactación/calidad razonable).

- UX de chat
  - RNF-036: Mantener orden cronológico de mensajes y estado de lectura coherente.

- Integridad referencial lógica
  - RNF-037: Garantizar que `pets.user_id` exista antes de crear la mascota.

- Seguridad de escritura
  - RNF-038: Evitar sobreescrituras concurrentes mediante reglas/estrategias transaccionales donde sea necesario.

- Latencia percibida
  - RNF-039: Operaciones críticas (envío de mensaje, cambio de estado) deben reflejarse en <1s en UI bajo red normal.

- Respaldo y recuperación
  - RNF-040: Mantener procedimientos de backup de datos críticos (p.ej., vía exportaciones periódicas).

- Soporte técnico
  - RNF-041: Registrar incidencias y permitir diagnóstico básico.

- Calidad visual
  - RNF-042: Mantener recurso gráfico coherente (iconos, imágenes) en `assets/`.

- Seguridad de hosting
  - RNF-043: Deshabilitar listado de directorios públicos, servir solo archivos necesarios.

- Consistencia cross-platform
  - RNF-044: Ajustar diferencias de capacidades (web vs móvil) con fallbacks razonables.

- Tratamiento de errores de Vision
  - RNF-045: Manejar errores de API y límites de cuota con mensajes claros.

- Eficiencia de caché AI
  - RNF-046: Verificar hash antes de invocar Vision para minimizar llamadas.

- Privacidad en chats
  - RNF-047: No exponer datos personales en mensajes del sistema.

- Seguridad de enlaces
  - RNF-048: Validar y sanitizar texto de mensajes para evitar inyecciones de contenido.

- Persistencia consistente
  - RNF-049: Asegurar que operaciones que actualizan múltiples campos (p.ej., `last_message` y contador) se apliquen atómicamente cuando sea posible.

- Mantenibilidad de dependencias
  - RNF-050: Mantener versiones compatibles y actualizar con changelogs.

- Gobernanza
  - RNF-051: Documentar roles/permisos si se amplían (moderación, rescate).

- Eficiencia de desarrollo
  - RNF-052: Scripts de configuración y build reproducibles.

- Interoperabilidad de datos
  - RNF-053: Exportar/importar datos clave para análisis (CSV/JSON) cuando se requiera.

- Seguridad de API keys
  - RNF-054: No incluir claves en repositorio público; usar mecanismos seguros.

- Monitorización básica
  - RNF-055: Medir uso de funciones críticas (publicación, envíos de mensajes) para mejoras.

- Estrategia de escalado
  - RNF-056: Diseñar para separar lectura y escritura en Firestore si el tráfico crece.

- Robustez de UI
  - RNF-057: Evitar crashes por datos inesperados (nulls, tipos incorrectos).

- Calidad de imágenes
  - RNF-058: Recomendaciones de tamaño/aspecto para fotos en publicaciones.

- Disponibilidad de contenido legal
  - RNF-059: Mantener accesibles y actualizadas páginas de privacidad y términos.

- Eficiencia en notificaciones
  - RNF-060: Evitar notificaciones innecesarias y agrupar cuando sea pertinente.
